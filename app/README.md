# KET 词匣（Phase 4）

纯前端 KET 选词、学习与双向背诵应用。词库随构建产物发布；用户的临时选择、生词收藏和背诵列表均保存在浏览器 IndexedDB，不需要注册。

## 页面与功能

- `#/`：列表总览、生词本去重计数与选词入口；
- `#/select`：按官方 A–Z 顺序在 10 列紧凑网格中选择全部 1723 个词；
- `#/lists/:listId`：列表详情、改名、移除词条，以及学习/背诵入口；
- `#/lists/:listId/learn`：连续滚动学习页，完整显示单词、音标、词性、释义和双语例句；
- `#/lists/:listId/recall`：看英猜中/看中猜英双向背诵，支持键盘、进度、答案状态记忆和全局星标；加 `?favorites=1` 只背该列表生词；
- `#/favorites`：跨列表生词本，可按最近标记或主题排序，并显示首次来源；
- `#/favorites/learn`、`#/favorites/recall`：生词本学习和背诵。

学习模式采用连续滚动而非分页：可以快速纵向浏览列表的所有六个字段，更符合“先认脸”的使用场景。背诵模式则固定为单卡，每轮开始时使用 Fisher–Yates 独立洗牌，本轮内顺序保持不变。看英猜中时英文例句和朗读按钮位于英文提示区，只有点击下方眼睛答案区才会揭晓中文；看中猜英时词性以独立标签显示，英文答案和朗读按钮仅在揭晓后出现。答案区使用固定最小高度避免揭晓时布局跳动，未揭晓答案使用条件渲染，不会进入 DOM 或无障碍属性。

## 选词页交互

选词页不再按主题拆分，而是保持 `vocab.json` 的官方顺序，将全部 1723 个词按每行 10 个平铺。词格只显示单词；长词在一行内省略，桌面端悬停可通过原生提示查看全文。每 50 个词有一个区间定位分割线，每 100 个词的分割线会稍加强调。

- 批量选择关闭（默认）：页面可以正常纵向滚动，点击一个词即可切换选择。
- 批量选择开启：按住并拖过词格可连续选择或取消。起手格决定本次手势的统一目标状态；同一格来回经过不会再次翻转。靠近列表上下边缘 48px 时会自动滚动，松手后可在 3 秒内撤销，开关保持开启以便连续操作。
- 范围输入使用全局序号 `1..1723`，例如 `21-40`，可批量加入或移除。
- 页面在滚动停止 500ms 后按稳定词条 ID 记住位置；临时选择保存 24 小时。创建列表的默认名称为 `YYYY-MM-DD KET 词表`，创建后清空临时选择并提供 5 秒撤销。

网格采用 `@tanstack/react-virtual`：每 10 个词组成一个虚拟网格行，分割线作为独立虚拟项插入，因此分割线横跨整行且不占用词格列。

## TTS 配置

生产环境默认请求同源 `/tts`，可在构建时通过 `VITE_TTS_BASE` 覆盖。开发环境的 `.env.development` 已配置：

```dotenv
VITE_TTS_BASE=http://127.0.0.1:3115
```

默认使用 `en-GB-SoniaNeural`、`0.85×` 语速，界面可选择 `0.5×–1.2×`。每次朗读依次尝试用户选择的引擎，然后按 `edge → tencent → minimax → glm` 尝试尚未在本会话失败的云端引擎，最后使用可用的 Web Speech API。主动停止产生的 `AbortError` 不会触发回退。界面的“实际”字段显示本次真正发声的引擎；所有引擎不可用时只显示友好提示，不影响文字学习。

## 开发与验证

要求 Node 24、npm 11。

```bash
npm install
node scripts/build-data.mjs
npm run dev
```

生产构建必须直接使用 Vite，以避开低内存机器上 `tsc -b` 的峰值内存：

```bash
npx tsc --noEmit
npm test
npx vite build
```

请勿在此机器运行 `npm run build`；该脚本保留标准的完整构建语义，但包含 `tsc -b`。

## 数据生成与稳定 ID

`scripts/build-data.mjs` 读取项目根 `data/ket_vocab_dataset.json`、`a2key_topics.json` 和 `topic_mapping.json`，生成：

- `src/data/vocab.json`：1723 条只读词库，增加冻结 ID；
- `src/data/topics.json`：25 个主题及对应词条 ID；
- `scripts/vocab-id-map.json`：单词到稳定 ID 的冻结映射，是后续数据迁移的依据。

生成器不会根据数组位置重算已有 ID。词库重排或释义修订仍按 `word` 回填旧 ID，新词仅从 `nextNumber` 追加。当前权威数据的 `word` 唯一；若未来出现同名单词，脚本会明确中止，要求先设计并提交显式迁移，避免静默改错 ID。`src/data/` 是生成产物，请勿手改。

## 本地数据结构

IndexedDB 数据库 `ket-vocab` 当前版本为 2，访问统一经过 `src/db/repository.ts`：

- `lists`：`id`、预留的 `profileId`、名称、有序且去重的 `vocabIds`、创建/修改时间；
- `selections`：单档案临时选择和更新时间，读取时自动清除超过 24 小时的数据；
- `favorites`：全局生词收藏、收藏时间与可选的首次来源列表 ID；v1 数据自动无损升级，旧收藏因没有来源元数据会显示“来源列表已删除”。

`localStorage` 只保存 A–Z 词表的稳定词条 ID 滚动锚点（旧版主题锚点即使仍存在也不会影响当前页面）。IndexedDB 打开或写入失败时，页面会显示明确的降级提示。

## 主要实现选择

- `HashRouter`：应用可直接部署到任意静态目录，不要求服务器配置 history fallback。
- `@tanstack/react-virtual`：只挂载可视行与少量 overscan 行，保持长列表滚动成本稳定。
- `idb`：保留原生 IndexedDB 的事务语义，同时减少样板代码；UI 不直接访问数据库。
- 批量手势状态机：按下时冻结“选择/取消”目标和撤销快照，以全局词索引去重；边缘 48px 内按深度线性加速，最高 600px/s。
